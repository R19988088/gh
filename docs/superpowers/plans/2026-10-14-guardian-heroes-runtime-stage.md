## 执行顺序

### 1. 接入 GPU 插件

- [x] 将 `guardian_heroes/CMakeLists.txt` 的最后一个调用改为：

```cmake
rexglue_setup_target(guardian_heroes GPU_PLUGINS xenos)
```

现有 `generated/rexglue.cmake` 会透传参数，SDK 的 `rexglue_configure_target` 已负责插件依赖及复制；无需修改生成文件或增加复制脚本。

- [x] 按 README 的既有配置与构建命令执行增量构建，确认插件构建成功并暂存到可执行文件旁。

### 2. 首次受控启动

- [x] 从工作区根目录使用显式参数启动：

```sh
./guardian_heroes/out/build/mac-arm64-release/guardian_heroes \
  --gpu_plugin=xenos \
  --game_data_root='/Users/ddd/Documents/xbla-守护英雄/guardian_heroes/assets' \
  > logs/runtime-first-launch.log 2>&1
```

- [ ] 按顺序确认动态库与插件加载、Vulkan／MoltenVK 初始化、XEX 执行和游戏资源读取。记录首个实质阻塞；窗口出现不算标题画面通过。
- [ ] 如果崩溃，保存调用栈、PPC 地址和对应日志；如果停滞或黑屏，区分 guest 执行、资源读取、视频播放、GPU 提交和呈现中的具体停点，再决定改动。

### 3. 处理实际触发的运行适配缺口

- [ ] 对首个阻塞做最小修复并验证该路径，恢复推进后再处理下一个。

- [ ] 若停在内容许可或用户状态，先确认实际返回值及原游戏分支；SDK 默认许可掩码为零不能直接推导为启动失败原因，也不预设修改掩码。
- [ ] 若停在开场 WMV 或资源加载，定位原播放／加载路径。需要跳过内容、替换画面或改变输入行为时，先与用户确认。

## 验证安排

用户已确认 GPU 增量构建与启动／标题菜单验证。追加 GPU 帧读回及渲染链路诊断待确认，预计 15–30 分钟，区分 guest 输出、resolve 与最终呈现的黑屏来源，失败后只修对应路径。

| 验证 | 预计耗时 | 检测的具体失败 | 失败后的行动 |
| --- | --- | --- | --- |
| 插件接入后的增量构建 | 5–20 分钟，取决于 GPU 目标缓存 | GPU 编译、链接、插件暂存失败 | 修复对应构建路径，暂不启动游戏 |
| 首次受控启动 | 3–5 分钟观察窗口 | 动态库／GPU 初始化失败、崩溃、黑屏或停滞 | 保存首个阻塞的日志与栈，定位所属层 |
| 标题菜单与一次重启 | 到达标题后约 5–10 分钟 | 无实际画面、输入无响应、重启无法复现 | 修复呈现、输入或启动状态的具体路径 |

这些是验证耗时估计，不是完成运行适配的工期承诺。已经通过的解包与 CPU 代码生成不重复全量验证，除非相关输入或实现改变。
